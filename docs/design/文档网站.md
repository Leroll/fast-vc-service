# 文档网站

## 1. 内容与构建职责

网站使用 [MkDocs](https://www.mkdocs.org/) 与 [Material](https://squidfunk.github.io/mkdocs-material/)，发布目标为 [GitHub Pages](https://leroll.github.io/fast-vc-service/)。Markdown 是唯一正文来源；导航与主题由 [mkdocs.yml](../../mkdocs.yml) 配置，构建不加载 Fast-VC 服务或模型。

[文档工具项目](../../tools/docs/pyproject.toml)及其 [uv.lock](../../tools/docs/uv.lock) 独立锁定依赖。服务根目录的依赖与锁文件继续只负责服务环境。

中文为默认界面，English 导航使用现有英文译文；两种语言共用客户端搜索。译文范围仍由[文档索引](../README.md#3-多语言维护)维护。主题关闭外部字体请求，主要导航优先呈现用户指南、API、设计和评测；历史资料、Spec 与每日记录保留链接访问能力。

Spec、每日工程日志、历史归档、旧路径跳转页和旧性能报告不进入全文搜索，避免历史参数与当前用户指南混排。

## 2. 本地预览与验证

安装 uv 后，在仓库根目录执行：

```bash
uv run --project tools/docs --python 3.12 --locked mkdocs serve
```

按终端显示的网址打开预览。站点带有 `/fast-vc-service/` 项目路径，与默认 Pages 地址一致。只预览文档不需要 CUDA、音频系统库或子模块初始化。

完整验证命令：

```bash
uv run --project tools/docs --python 3.12 --locked mkdocs build --strict
uv run --project tools/docs --locked python tools/docs/check_site.py
git diff --check
```

网页写入被 Git 忽略的 `site/`。严格构建检查文档链接与锚点；网页检查补充检查最终 HTML 的站内链接、资源和锚点，不联网检查外部网站可用性。

更新工具依赖时，修改文档项目的 pyproject.toml，再执行 `uv lock --project tools/docs --python 3.12`，提交声明与锁文件并重新构建。不要为文档安装服务依赖。

## 3. 路径与链接适配

[构建钩子](../../tools/docs/hooks.py)在内存中生成三个页面，不回写源文件：

| 来源 | 网站中的页面路径 |
| --- | --- |
| 根 README.md | project.md，项目介绍 |
| 根 CONTRIBUTING.md | contributing.md，贡献指南 |
| docs/en/README.md | en/project.md，英文项目介绍 |

文档首页使用 docs/README.md；英文用户索引使用 docs/en/index.md。英文项目介绍使用独立网址，避免 MkDocs 将同目录的 README.md 与 index.md 都映射到 index.html。

Markdown 渲染时，钩子根据原文件位置解析相对链接：已纳入网站的 Markdown 指向对应网页，源码、配置、音频、协作规则等指回 GitHub 的 main 分支，已有图片引用使用公开 raw 地址。不存在或越出仓库的相对链接会使构建失败。原生 HTML 的 href/src 同样处理，代码示例不改写。

发布产物仅包含文档和主题资源，不复制源码、音频、模型、日志、会话数据或 .env。新增静态素材仍需按协作规则核对来源和可发布范围。

## 4. 自动构建与发布

[工作流](../../.github/workflows/docs.yml)的行为：

- PR 修改文档、文档工具、相关入口或工作流时，执行构建与网页检查，不部署。
- main 分支发生上述改动时，验证通过后上传 Pages artifact 并部署。
- 支持手动运行；选择 main 时部署，选择其他分支时只验证。
- 构建任务只有仓库读取权限；部署任务具有 pages: write 与 id-token: write，使用 github-pages 环境。
- 部署任务串行执行，不中断已开始的部署；不使用 gh-pages 分支，不提交生成的 HTML。

首次发布由仓库管理员在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。提交并推送工作流后，可在 Actions 中运行“文档构建与发布”。若仓库对 github-pages 环境设置了审批或分支保护，发布遵循现有规则。

默认网址为 <https://leroll.github.io/fast-vc-service/>。迁移仓库或使用自定义域名时同步调整 site_url、repo_url、构建钩子的源文件链接和文档入口。云端工作流完成且网址可访问后，才算首次上线完成。

## 5. 故障排查与验证边界

- 构建报相对链接不存在：检查目标文件与原 Markdown 的相对位置，不通过关闭严格验证隐藏问题。
- 新页面未出现在导航：在 mkdocs.yml 的 nav 中添加；仅用于历史追溯的页面明确放入 not_in_nav。
- 网站页面或样式 404：检查 site_url 的项目子路径，以及部署产物是否为 site 目录。
- 部署提示 Pages 未启用或权限不足：检查发布来源、部署任务权限和 github-pages 环境规则。
- 中文搜索失败：检查 jieba 安装、搜索索引生成与浏览器端搜索资源加载。

本地构建、网页检查与浏览器预览验证展示层；GitHub Actions 运行和 Pages 线上访问另行验收。它们都不代表语音服务、GPU 推理、音质或并发性能已测试。

## 6. 维护周期与后续方向

当前文档环境使用 Python 3.12、MkDocs 1.x 和 Material 9.8，并由 uv.lock 锁定。Material 上游已进入维护阶段，关键修复支持至 2027-05-05；依据见[官方发布记录](https://squidfunk.github.io/mkdocs-material/changelog/)。当前网站可以继续使用，后续升级需评估主题支持周期和构建钩子的兼容性。Zensical 或其他主题是可评估方向，本任务未实施迁移。
