# 模型加载与推理

## 1. 模型加载

[ModelFactory](../../src/fast_vc_service/models.py) 负责加载 DiT/CFM、内容编码器、声码器、说话人特征模型、Mel 变换、VAD，以及按开关加载的 F0 和检索组件。

默认模型通过 Hugging Face 获取，VAD 使用 FunASR / ModelScope。缓存路径由 .env.example 中的环境变量配置，首次下载不是服务推理性能的一部分。

当 `dit_checkpoint_path` 与 `dit_config_path` 均提供时加载自定义模型，否则使用 `defalut_original_model` 的模型映射。后者保留了源码中的拼写，文档不能自行更名。tiny、small、base 会关联不同模型配置，替换时须核对模型采样率、声码器和音高需求；不能仅改名称就承诺运行兼容。

默认 tiny 路径不是上游所有模型能力的统一入口。服务初始化断言 `SAMPLERATE_OUT` 与模型采样率相等。

## 2. 参考音色

每个 Worker 启动时读取 `reference_wav_path`，按 `max_prompt_length` 截取，并计算：

- 16 kHz 参考音频的内容特征；
- CAMPPlus 风格特征；
- 模型采样率下的 Mel 与参考条件；
- 开启自适应音高时的参考音高统计。

参考条件在 Worker 内复用。当前协议不包含每会话替换参考音频的操作；更换参考路径后需重启相应服务。多个固定音色可使用不同配置和端口的实例，运行资源隔离见[部署说明](../getting_started/配置与部署.md)。

## 3. 流式推理

当前链路在 Session 上维护 VAD 缓存、音频窗口和拼接状态。VAD 影响有声判断与上下文策略；F0 开关控制是否提取音高并使用参考统计进行调整。

内容编码后可执行 FAISS 语义检索：按检索距离加权得到特征，再通过 `index_rate` 与原特征混合。启用时需要与内容编码特征匹配的索引，配置中的示例索引路径不表示仓库已附带索引文件。

对齐后的条件与参考条件拼接，DiT/CFM 生成目标特征，再经声码器生成音频。模型工厂为 CFM 安装线性或余弦 `t_span_schedule`，推理步数由 `diffusion_steps` 控制。后处理见[音频约定](流式处理与音频约定.md)。

## 4. 调参与验证

调整模型、步数、上下文、检索和音高参数会同时影响效果与开销，必须保持输入、参考音频及其余条件可比较。记录有效配置，而非只记录“默认参数”。

当前有可选 `torch.compile` 路径，部分编码器内部采用半精度；这不等于提供统一、已验证的全链路 fp16 开关。启动后应检查日志中实际模型、设备和配置，再做[性能与效果评测](../evaluation/README.md)。

模型权重、上游代码及数据可能分别具有自己的使用条款；仓库 LICENSE 说明本项目代码许可，不能代替所选模型与素材的说明。
