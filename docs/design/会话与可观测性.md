# 会话与可观测性

## 1. 会话生命周期

[WebSocket 路由](../../src/fast_vc_service/routers/ws.py) 接受连接后解析首条 JSON，识别标准或简单协议，经统一配置创建 Session 与 Buffer。标准协议返回 ready，简单协议不返回 ready。

每个 [Session](../../src/fast_vc_service/session.py) 保存音频上下文、VAD 缓存、音高与 RMS 状态、SOLA 缓冲、输出数组、音频记录和时间线。每个连接独立持有会话，模型由 Worker 复用。客户端应使用唯一、适合文件名的会话标识；当前没有租户命名空间或完整标识校验。

收到正常结束消息后，服务处理尾块并返回完成消息。超时或断联则退出收包循环；最终清理连接计数和 Buffer，并创建后台 Session 保存与清理任务。

## 2. 输出与完成语义

`save_input` / `save_output` 控制音频记录，输出保存在 `save_dir/YYYY/MM/DD/`，包括会话 ID 对应的 input.wav、output.wav 和 timeline.json。保存日期取服务进程运行时钟，不是文档日志所约定的北京时间。

输入保存的是经过缓冲和重采样、送入推理链路的音频，不是原始 WebSocket 字节；输出按协议输出采样率保存。预填充、尾部补齐及后处理可能改变时长。

保存通过后台任务在线程中执行。complete 表示正常协议处理结束，不表示落盘已完成；进程强制退出也可能中断保存。异常断联后会尝试保存已经记录的部分，不保证未处理尾块得到转换。

会话工具接口读取已保存文件，见 [HTTP API](../api_docs/http-api.md)。

## 3. 日志、连接与时间线

日志包含 Worker、会话、各推理阶段耗时及 SLOW 标记。ConnectionMonitor 用进程内集合统计连接，并通过带文件锁的 `temp/connections.json` 汇总同一工作目录内的 Worker 记录。

当前 CLI 的 PID 文件按端口命名，而连接监控仍使用上述公共文件。同一目录多实例的连接统计可能混合；不同配置的日志与输出也要显式区分。

Session 中 SEND 表示客户端送入音频，RECV 表示客户端方向收到服务输出。名称采用客户端视角；不要按服务端收发方向直接解读。时间线分析工具在离线阶段计算指标，当前没有 `/tools/performance-report` 路由。

## 4. 已知测量限制

- 当前路由记录输出音频时长时按 16000 Hz 计算；当 `sample_rate_out` 不为 16000 Hz 时，服务端时间线累计时长存在偏差。
- 路由的 E2E 日志只计取块、转换和发送这段执行时间，未包含输入累积、采集或客户端播放。
- 路由的 VC_SLOW 比较使用秒计时值，而配置阈值按毫秒命名/说明；不能把该标记作为完整时延验收依据。
- 部分处理异常仅写日志或补静音，协议没有保证每次内部失败都返回结构化错误；complete 也不是音频质量验收。

这些是按当前源码记录的限制，本次未修复实现。新测量应先核对事件来源、采样率和时间单位，具体方法见[评测指南](../evaluation/README.md)。
