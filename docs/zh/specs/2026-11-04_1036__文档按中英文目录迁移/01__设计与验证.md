# 文档按中英文目录迁移

## 1. 背景与目标

现有 docs 将主题目录与 en 语言目录并列，中文的语言归属隐含在根层级。本次按维护者要求，将中文文档集中到 docs/zh，英文集中到 docs/en，同步链接、导航、内容检查与协作约定，保持现有网站地址和公开锚点不变。

状态：已完成。仅调整文档组织和网站适配，不修改服务、配置、客户端、模型或依赖版本。

## 2. 目录与行为

- 根 README.md、CONTRIBUTING.md、AGENTS.md 保持原位置；docs/README.md 成为仓库内的语言导航，不生成独立网页。
- 原中文用户索引迁到 docs/zh/README.md，继续生成网站首页；中文主题目录、设计、Spec、工程日志、评测和 todo 整体迁入 docs/zh。
- docs/en 的既有页面保持位置；英文版本历史从 docs/changelog/releases_en.md 移到 docs/en/changelog/releases.md，正文保留，其网站地址继续为 changelog/releases_en/。
- docs/website 保持共用，图片、音频、源码及配置不复制。历史归档保留其原语言，不为语言目录重新翻译历史正文。
- 已有翻译范围不扩大，中文用户索引与英文 index.md 继续成对；目录入口和英文项目主页保留各自职责。
- 所有现行相对链接按新位置更新；历史记录仅调整可点击链接，保留当时的路径描述、日期、结论和依据。

## 3. 网站兼容与设计取舍

构建来源仅包含根项目/贡献入口与 docs/zh、docs/en，排除仓库语言入口和网站工程。中文来源去掉 docs/zh 前缀映射到原网址；英文沿用 en 前缀，英文版本历史单独保留旧地址。保持一份正文来源，不复制兼容 Markdown。

页面的历史标记、搜索排除、首页布局和协议提取适配新的语言前缀；翻译映射与源码复核映射更新为新来源。网站导航继续使用既有公开网址，源码链接改为新路径。GitHub main 的旧文件路径随迁移改变，历史提交和标签仍可查看旧位置；本次保持的是网站地址。

## 4. 实施步骤

1. 保存迁移前全部页面的来源、网页路径及历史/搜索属性。
2. 移动文件，更新相对链接、现行路径文字、双语入口及文档约定。
3. 更新构建来源、路由、首页识别、翻译和检查脚本，补充路径兼容回归。
4. 执行文档内容检查、Python 与 Node 回归、生产构建、网页链接/锚点/搜索检查；逐页比对迁移前后的网页路径与属性。
5. 更新当前设计、Spec 验收、索引和当日 changelog；不提交、不推送、不发布。

- 迁移前每个网页都有唯一的新 Markdown 来源，网址及公开锚点保留；不生成多余的 zh/ 站点层级。

- 旧 Spec、工程日志和历史资料除必要链接外保持原文；历史评测报告逐字节一致。
- git diff --check 通过，无服务源码、配置、模型、依赖或公开素材变更。
- 本地验证不代表 Pages 已部署；不进行服务联调、GPU 推理、音质或压力测试。
