# 需求、设计与验收

## 1. 建档规则

重要功能、重构、协议、配置语义、推理链路和部署变更先建 Spec；小修复与一般文档调整可仅记 [changelog](../changelog/README.md)。纯讨论与只读分析不建档。完整协作规则见 [AGENTS.md](../../AGENTS.md)。

目录采用建档北京时间 `YYYY-MM-DD_HHmm__中文任务名/`，默认文件为 `01__设计与验证.md`，续做任务更新原目录，不建立空模板。

## 2. 内容与状态

记录背景、目标、范围、需求行为、设计取舍、实施步骤、兼容影响、验收标准、实际验证、未验证范围和剩余问题。方案变化先更新记录，再实现；已授权工作不因建档另设审批。

语音相关任务按需记录模型/子模块版本、配置、硬件、源音频与参考音频、输入输出采样率、分块参数和评测方法。素材未公开时记录可公开的复现条件，不附内部资源地址。

状态区分实施中、已实现待验收、已完成。Spec 保存任务历史，[design](../design/README.md) 维护当前设计；完成后同步二者及 changelog。
